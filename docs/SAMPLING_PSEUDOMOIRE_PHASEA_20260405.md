# Sampling-Aware Pseudo-Moire Prototype Phase A (2026-04-05)

## 1. Purpose and Scope

This note records the **first inversion-side sampling-aware prototype** implemented after the earlier map-domain and simple SH-domain HSA families had already failed.

The purpose of this Phase A attempt was not to immediately beat `DDK4`, but to verify a narrower hypothesis:

- whether **monthly orbit bundle geometry** and **low-degree carrier field** can provide a more physically meaningful stripe subspace in spherical harmonic (`SH`) space;
- whether that stripe subspace is more concentrated and interpretable than the earlier map-domain heuristics;
- whether a constrained separation in `SH` space, performed **before EWH synthesis**, can reduce severe-month striping without excessive land-signal loss.

This document covers:

- background;
- theoretical basis;
- algorithm design;
- implementation details;
- test configuration;
- numerical and visual outputs;
- conclusions and next steps.

## 2. Background

### 2.1 Why a new direction was needed

Earlier experiments had already shown a stable pattern:

- `grid-domain HSAF` variants did not robustly remove GRACE stripes;
- `map-domain adaptive modal scoring` also failed;
- `simple SH-domain HSA / demodulation` remained weaker than `DDK4`;
- `orbit-aware post-filtering` on final monthly `EWH` maps still failed.

The common failure mode was not merely "bad weights" or "insufficient smoothing". The deeper issue was:

> the methods were still operating **after** spherical harmonic inversion and `EWH` synthesis, while the dominant stripe component is believed to arise from the coupling of **sampling geometry**, **low-degree carrier field**, and the **inversion process** itself.

That is why this attempt moved the prototype to the **inversion side**.

### 2.2 Literature motivation

This prototype was motivated by two literature strands:

1. **Hankel Spectrum Analysis (HSA)** literature  
   HSA is useful when the target residual can be decomposed into a small number of interpretable modes.  
   However, our previous experiments indicated that HSA alone is too burdened if it must separate stripe and signal directly from the full monthly field.

2. **Peidou et al. on GRACE stripe origin**  
   The Peidou papers argue that the dominant north-south stripe pattern is not just generic random high-frequency noise. It is better interpreted as a structured `pseudo-moire / sub-Nyquist` artifact caused by the interaction of:
   - monthly ground-track bundle geometry;
   - low-frequency background carrier field;
   - sampling/inversion mapping.

This naturally suggests the following modeling move:

- instead of filtering the final `EWH` map;
- construct an explicit **stripe-generating proxy basis in SH space**;
- then separate `signal_SH` and `stripe_SH` before synthesis.

## 4. Theoretical Basis

### 4.1 Physical intuition

The working physical intuition of this Phase A prototype is:

1. the monthly low-degree field acts as a **carrier**;
2. monthly orbit bundle geometry introduces a **directional sampling modulation**;
3. the interaction of the two produces a structured stripe-like component in `SH` residual space.

In plain form:

```text
total_SH = signal_SH + stripe_SH + residual_SH

stripe_SH is not treated as arbitrary noise.
It is assumed to lie near a subspace generated by:

    stripe_basis ~= coupling(bundle_geometry, low_degree_carrier)
```

### 4.2 Why SH space instead of final EWH map

The earlier map-domain failures suggested that by the time the final monthly `EWH` field is available:

- the physically relevant coupling is already mixed into the synthesized map;
- simple filtering or regression on the final grid cannot recover the generating structure;
- map-domain pattern fitting tends to remove real signal together with stripe.

So this prototype moved the separation to the `SH` domain, before map synthesis.

### 4.3 Simplified MVP mathematics

This Phase A prototype intentionally avoided a full Gaunt / Wigner `3-j` implementation.

Instead, it used a first-order approximation:

```text
carrier_SH  -> low-degree background field, truncated to l <= 20 and m <= 10
bundle_grid -> monthly ground-track density proxy
bundle_order_amplitude(m) -> longitude-spectrum amplitude derived from bundle_grid

order_risk(m) ~ scaled coupling of:
    bundle_order_amplitude(m)
    carrier_order_power(m)
```

The stripe candidate basis for each `order m` was built from the carrier profile scaled by the bundle amplitude.

For each `order m`, the basis columns were:

```text
phi_base(m)      = direct carrier profile scaled by bundle amplitude
phi_ramp(m)      = degree-ramp weighted version of phi_base
phi_roughness(m) = second-derivative-like version of phi_base
```

The constrained separation solved an approximation of:

```text
x_total = x_signal + Phi * alpha + x_residual

minimize:
    ||x_total - x_signal - Phi * alpha||^2
  + lambda_signal * smoothness(x_signal)
  + lambda_stripe * risk(m) * ||alpha||^2
```

This is still an MVP. It is not yet a full pseudo-moire forward operator.

## 5. Algorithm

### 5.1 Input assumptions

Phase A used:

- input tag: `P4M6`
- monthly SH coefficients reconstructed from the pipeline context
- monthly orbit bundle geometry from `GNV1B`
- a low-degree carrier truncated to:
  - `l <= 20`
  - `m <= 10`

### 5.2 Orbit bundle data path

The experiment first attempted:

- monthly `RL03` bundle build

But a real blocker appeared:

- `RL03` monthly archives in the tested source did not provide usable `GNV1B` for this path

So the implementation added a fallback:

- sample `RL02` daily `GNV1B` files across the month
- default sampled days for this Phase A run:
  - 3 days per month
- missing sampled day files were retried within a `+/- 2` day local window

This was implemented in:

- `G:\GRACE_Level2_pipeline_exc\python\grace_pipeline\app\grace_groundtrack.py`

Relevant functions:

- `build_monthly_groundtrack_bundle_rl02_sampled(...)`
- `_sample_days_for_month(...)`
- `_nearby_days(...)`

### 5.3 Operator implementation

The core class is:

- `PseudoMoireOperator`

Defined in:

- `G:\GRACE_Level2_pipeline_exc\python\grace_pipeline\inversion\pseudo_moire.py`

Relevant methods:

- `fit(...)`
- `build_basis(...)`
- `separate(...)`
- `diagnostics(...)`

Key implementation choices:

1. **carrier truncation**
   - keep only low-degree carrier coefficients

2. **order-risk profile**
   - not only fixed `m = 4, 8, 12`
   - also auto-augment with the strongest bundle-amplitude orders

3. **basis enrichment**
   - direct carrier profile
   - degree-ramp column
   - roughness column

4. **channel-wise separation**
   - solve cosine and sine channels order by order

### 5.4 Pseudocode

```text
for each target month:
    load P4M6 monthly SH coefficients
    build monthly bundle density from orbit tracks
    if RL03 bundle is empty:
        fallback to RL02 sampled daily GNV1B

    operator.fit(bundle_density, C_in, S_in, lat_vec, lon_vec)

    [C_sig, S_sig, C_str, S_str, C_res, S_res] = operator.separate(C_in, S_in)

    synthesize:
        signal_grid  = EWH(C_sig, S_sig)
        stripe_grid  = EWH(C_str, S_str)
        residual_grid = EWH(C_res, S_res)

    compute diagnostics:
        order risk profile
        stripe energy by order
        residual energy by order
        basis concentration score

    compare signal_grid against DDK4 and current HSAF baseline
```

## 11. Implementation Observations

### 11.1 What improved compared with previous attempts

Compared with earlier orbit-aware post-processing attempts, this run improved in three concrete ways:

1. **Real orbit geometry actually entered the operator**  
   The experiment no longer relied on empty or degenerate bundle inputs.

2. **The basis was no longer vacuous**  
   The basis was expanded from a single direct-product column to:
   - base profile
   - degree ramp
   - roughness profile

3. **Risk orders were no longer fully fixed**  
   The implementation augmented `4/8/12` with the strongest bundle-amplitude orders of the month.

## 12. Failure Analysis

### 12.1 Why the run still failed

The Phase A failure can be summarized as:

> the prototype began to identify a more concentrated SH subspace from real orbit geometry, but it still did not identify the **correct** pseudo-moire stripe subspace.

The likely reasons are:

1. **direct-product basis is still too weak**  
   The true coupling is more complicated than:
   - order-wise bundle amplitude
   - multiplied by carrier profile

2. **degree coupling is still under-modeled**  
   The MVP basis enriches the degree direction only with simple ramp and roughness columns.  
   It does not yet approximate the true triad / Gaunt-like coupling geometry.

3. **the current separation is still regularized too generically**  
   It is better than plain smoothing, but it is still not a strong generative forward model of pseudo-moire production.

### 12.2 What the experiment nevertheless validated

Even though the destriping quality was poor, the run still validated several important facts:

- orbit geometry can be injected into the SH-side prototype;
- severe-month risk is not well represented by fixed orders alone;
- the monthly bundle-risk structure is not uniform across months;
- the next operator should focus on **stronger SH coupling**, not more map-domain heuristics.

## 13. Recommended Next Step

The correct follow-up is **not** to continue tuning:

- `lambda_stripe`
- `lambda_signal`
- sampled-day count only

The next meaningful step should instead strengthen Direction 1 itself:

1. replace the current order-amplitude proxy with a stronger `SH coupling basis`;
2. introduce degree coupling closer to a Gaunt-like triad approximation;
3. let the operator act on a month-specific dominant risk set instead of a mostly fixed order scaffold.

Only if that stronger SH-side pseudo-moire basis starts to work should:

- residual-only HSA refinement;
- adaptive DDK-like scheduling

be reintroduced.
